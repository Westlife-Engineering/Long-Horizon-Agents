## 合并稿第 14 页：能力内化的证据需要分层

**讲述目标：**说明“训练后成功率提高”还不能单独回答恢复与迁移问题。三个维度帮助判断具体学到了什么，不把它们讲成严格递进的三个能力等级。

**节奏：约 75–90 秒。** 承接上一页 Agentic RL 总览，用软件修复这个教学情境贯穿三个维度，最后留下一个讨论问题。

| 时间 | 讲述动作 | 听众应带走什么 |
| --- | --- | --- |
| 0–10 秒 | 承接：四个设计维度解释如何训练，现在看怎样解释训练后的改善 | 从训练方法转到能力证据 |
| 10–30 秒 | 当前配置：固定任务、接口和预算，修复成功率提高 | 支持这套条件下更可靠 |
| 30–50 秒 | 错误恢复：区分“更少改错文件”与“改错后更会恢复” | 总分提高可以来自不同机制 |
| 50–70 秒 | 条件改变：区分新题目、工具接口、环境与预算变化 | 换题成功不自动证明换接口也成功 |
| 70–90 秒 | 收束：哪种证据支持想声称的能力变化 | 评价与主张对应 |

### 可直接讲的版本

上一页概括了 Agentic RL 怎样采样、分配信用并更新策略。这一页进一步看，训练后分数提高，究竟说明学到了什么。

可以用代码修复来理解。第一，在同样的接口和预算下，修复成功率更高，说明当前配置下更可靠。第二，还要区分是更少犯错，还是犯错以后更会恢复。比如更少改错文件，与改错后能发现、撤回并继续修复，是两种不同的改善，最终成功率本身不能把它们分开。第三，是换条件以后还剩多少能力：换一道题、换一个工具接口，或者缩短交互预算，检验的并不是同一种迁移。

所以这页想保留的判断是，当前成功、错误后的恢复和跨条件迁移需要分别举证。讨论点是：什么证据足以支持“训练学到了可迁移的策略”，而不只是在当前配置下做得更好？

### 表达边界与追问

- 软件修复例子是教学情境，不是新增实验结果。已有结果若只测当前配置，就把结论留在该配置。
- 在既有 Harness 下学会更好的行为，也可以是能力内化；不要求移除工具或 Harness 才算内化。
- 如果被问“需要怎样测”：先说明要改变哪种条件、固定哪些预算，再看错误后的后续轨迹和任务结果。此处只给评价视角，不宣称已有完整实验方案。

依据：[[raw/surveys/Towards Long-Horizon Agents.pdf#page=40|S001 §5.2 · pp.40–43]]、[[raw/surveys/Towards Long-Horizon Agents.pdf#page=47|§5.5–5.7 · pp.47–55]]、[[raw/surveys/Towards Long-Horizon Agents.pdf#page=64|§6.6 · pp.64–65]]；三维组织与教学例子为本库归纳，参见 [[wiki/optimization/Questions|Optimization 问题]]。

## 合并稿第 17 页：已有成效依赖可用信息与有效反馈

**讲述目标：**用具体例子解释已有系统为什么有效，再以“局部正确还不够”收束整份汇报。按机制组织，避免逐篇复述论文或报分数。

**节奏：约 90–110 秒。** 每个机制配一个主例子，其他论文只作补充支点。

| 时间 | 讲述动作 | 主例子与限定 |
| --- | --- | --- |
| 0–10 秒 | 承接应用分类：换一个视角，看系统靠什么取得成效 | 以下是跨案例归纳 |
| 10–40 秒 | 先让模型拿到可用信息、做出可执行操作 | VideoSeek 的同帧对照；SWE-agent 的接口设计作为补充 |
| 40–70 秒 | 固定流程也能组织反馈并筛选结果 | Agentless 的定位、修复、测试选择流程；不推出固定流程总是更优 |
| 70–95 秒 | 检查完整目标和产物依赖 | Toolathlon 选对 checkpoint 却漏传图片的失败案例 |
| 95–110 秒 | 收束：定位任务中最缺的一环 | 信息、判断、有效反馈或完成条件 |

### 可直接讲的版本

前面按接口介绍了应用。这一页换一个角度，看这些系统的成效具体来自哪里。

第一，是把信息和操作整理成模型真正能用的形式。比如 VideoSeek 选择的视频帧，交给基础模型后也能改善回答，说明“看到了什么”本身就很重要；SWE-agent 的接口消融也说明，搜索和编辑怎样设计会影响结果。但这些证据不能把所有收益都归给推理能力。

第二，是让反馈参与结果选择。Agentless 用固定的定位、修复和测试选择流程，也能取得成效。因此，有效反馈不一定依赖模型自由规划每一步；这也不意味着固定流程在所有任务上都更好。

第三，是完整交付。Toolathlon 有个案例，Agent 已经选对 checkpoint，却漏传 README 依赖的图片，整个任务仍然失败。这个例子说明，局部答案正确之后，还要检查目标有没有漏项、产物依赖是否齐全。

因此，面对一个具体任务，可以先问：现在缺的是关键信息、对已有信息的判断、有效反馈，还是完整的完成条件？这比直接把失败全部归给模型或 Harness，更有助于确定下一步该查什么。

### 表达边界与追问

- VideoSeek 同帧对照支持证据选择有效，不能把完整系统的剩余差距全部归为纯推理，也未证明动态观察在同预算下一定更优。
- Agentless 是“自由规划并非取得成效的必要条件”的具体反例，不是固定流程普遍优于 Agent 的证明。
- Toolathlon 是一条失败轨迹，说明完整交付问题存在，不代表已测出该类应用最常见或最主要的瓶颈。
- 如果被问“优先改模型还是 Harness”：回到具体失败和对照证据。组件消融说明它有作用，不自动给出剩余改进空间的排序。
