## B1：验收者开始行动以后，验收对象还是同一个吗？

**一句话直觉。[归纳]** 会调用工具取证的检查者也在做事；“由另一个 Agent 检查”还没有说明它能否改动正在检查的结果。这是本轮尝试的非种子联系，连接主动验证与执行权限。

**原文锚点。[原文]**

- §4.6.2 将验证扩展到能推理、调用工具的 agentic verifier；终局验证还可通过在线主动交互确认 GUI 结果，而不只相信轨迹。这是综述转述，未读所引原论文。[[raw/surveys/Towards Long-Horizon Agents.pdf#page=36|S001 · §4.6.2 · p.36]]
- §4.3.1 区分单次调用接口与有状态环境中的连续调用，明确涉及 state mutation；工具交互不只是生成文字。[[raw/surveys/Towards Long-Horizon Agents.pdf#page=27|S001 · §4.3.1 · p.27]]
- §4.5 把 allow、block、hand-off 放在实际动作路径上；§4.5.1 的工具调用与协议边界检查参数及逐动作授权。[[raw/surveys/Towards Long-Horizon Agents.pdf#page=31|S001 · §4.5–4.5.1 · pp.31–32]]

**机制映射。[归纳]** 执行者和主动验证器都可能经历“读取状态→提出调用→接收观察”，因此可共享调用记录与状态标识，并接受动作边界约束。但二者的任务不同：一个改变环境以完成要求，一个取得足以判断要求的证据。若取证操作会改变被检查状态，最终通过究竟归因于原执行、检查者修复，还是两者联合，就需要另行区分。综述已明确验证器主动交互及 Hooks 执行控制；“检查前后状态与贡献归属必须分开”是本轮进一步归纳，现有概述未明确展开。

**关键差别。[归纳]** 放行验证器的工具调用，只说明允许执行；并不证明评价正确。检查者能发现错误，也不意味着已被授权修复。共享轨迹不要求共享写权限、评分目标或模型参数。

**最小思想实验。[假设]** 文献整理 Agent 声称笔记已保存，实际只有未保存草稿。检查者为确认保存，执行相同的“点击保存、重新打开”序列；唯一改变是该序列作用于隔离副本还是正式工作区。两种配置都可能读到完整文件，但只有后者替执行者完成了正式保存。设计取舍随之变为：评估原执行结果，还是明确验收整个修复闭环。

**最强反例。[假设]** 验证器只读，或在隔离副本中执行无外部副作用的测试时，这个冲突可能不存在；若产品本来就授权“检查并修复”，联合完成也完全合理。本卡不主张所有主动取证都会污染证据，更不据此无限递归地增加检查者。

**收窄问题。[假设]** 主动验证允许改变任务状态时，最少应保留哪些检查前状态与介入记录，才能分别回答“原执行是否完成”和“介入后系统是否完成”？本章未提供统一记录方案，也不能据此断言领域缺口。

## B2：下一次调用应补证据，还是继续判断？

**一句话直觉。[归纳]** 多评几遍一个缺少关键条件的结论，可能只是把同一份不完整依据用得更久；追加预算前先问这一步能增加什么。

**原文锚点。[原文]**

- §4.2.1 的 Selection 决定何时检索、构造何种查询、搜索何处及注入多少；太少可能丢失早期依赖，太多增加成本和噪声。[[raw/surveys/Towards Long-Horizon Agents.pdf#page=24|S001 · §4.2.1 · p.24]]
- §4.1.3 把分支定义为承诺前生成并评价替代方案；部分状态能被便宜且有意义地评价时才更有吸引力，弱、延迟或昂贵反馈会降低价值。[[raw/surveys/Towards Long-Horizon Agents.pdf#page=22|S001 · §4.1.3 · pp.22–23]]
- §4.6.3 已讨论验证引导搜索、宽度与深度调整，以及给判断本身增加计算；§4.6.2 还包含工具交互式验证。不能把“给验证更多预算”当成本轮新关系。[[raw/surveys/Towards Long-Horizon Agents.pdf#page=36|S001 · §4.6.2–4.6.3 · pp.36–37]]

**机制映射。[归纳]** 对同一未决结论，检索改变可见证据，分支扩展候选解释，验证改变对候选的评价。三者都能消耗下一份预算，但作用对象不同：候选里已有正确解释却缺判断依据，与根本没有可行解释，需要不同的后续操作。本轮增加的是按“本次调用实际改变什么”辨认开销；不是提出一套已验证的最优分配器。

**关键差别。[归纳]** 评价器也能检索，所以按角色名分配预算会误计：一次“验证调用”可能主要在补证据。共享结论、证据定位与未决条件，不等于统一质量评分与权限；强制执行约束也不能随预算紧张被取消。

**最小思想实验。[假设]** 固定同一模型、两个候选解释、总预算与可用工具，只改变原文限定段是否已在当前上下文。若段落仅在外部索引中，额外操作应先考虑取回；若已经可见，重读相同内容未必有益，比较解释或更细检查可能更合适。这是条件化判断，不能保证哪条路线收益更高。

**最强反例。[假设]** 现有信息可能足够推导正确答案，检索却引入噪声；反过来，有段落也不保证模型能理解。单一低置信度无法区分缺证据、缺候选和判断能力不足，因而不能直接驱动可靠路由。

**收窄问题。[假设]** 在再次增加判断调用前，能否先记录“哪个要求尚未判定、相关证据是否可见、可行候选是否存在”，并据此讨论下一项操作？这里只提出可审查的分配依据；诊断可靠性、不同预算如何比较仍属本轮材料不足。

两卡都保持“待讨论”状态；B1 强调主动判断的权限与归因，B2 强调追加计算实际改变的对象，均不要求合并各模块或增加 Agent 数量。


## 第二轮修订

依据 A 的交叉评议，保留两卡并收窄；首稿不改写。以下仍是综述内归纳与思想实验，不新增实证或新颖性主张。

**B1：收窄，并改写思想实验。** 接受“无关状态改变不等于修复任务”的反例：焦点、访问记录变化未必影响文件要求，不能据此要求完整快照。只关注可能把未满足要求变成满足的介入。固定同一正式工作区、未保存草稿、读取序列与判据，唯一改变是读取前是否执行一次保存；保存后的文件存在，只证明介入后达标，不能倒推原执行已完成。主动操作若本来就是测试要求的一部分，也不应禁止。修订后主张：[假设] **当验证动作可能使任务要求达标时，保留要求相关的介入前证据、动作及作用，分别评价原执行与修复后结果。** 不默认保存完整环境，也不因检查者身份取消写权限。

**B2：保留为审查清单，收窄分配含义。** 接受关键段虽在上下文却未被有效使用的反例；§4.2.1 本就提示信息利用退化。因此撤去任何“可见就应增加判断”的倾向，重新定位同一段仍可能值得。保留单变量实验，但它只说明可选操作及成本变化，不能判定最优选择。将“可行候选是否存在”改为记录候选及其尚未验证的条件，避免免费假定已知正确候选。修订后主张：[归纳] **追加调用前可登记未决要求、证据位置与读取记录、解释分歧及候选待验条件，再描述该调用预计改变什么；这些记录不证明证据已被使用，也不构成可靠诊断或自动路由规则。** 允许一次调用兼做取证、候选构造与评价，新增诊断本身也计成本。

两卡按上述限定交回主 Agent 综合；本轮讨论在此收束。
