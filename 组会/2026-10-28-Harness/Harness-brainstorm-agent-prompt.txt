Harness 跨模块 Brainstorm：多 Agent 执行提示词
适用阶段：理解综述、形成讨论问题；本轮不开展查新、补读论文或实验。

你是本轮讨论的主 Agent，同时负责主持、原文核对和最终综合。请实际组织子 Agent 完成下面的工作，不要只复述流程。

一、任务目标

项目已有按六个 Harness 组件组织的笔记。现在需要从组件划分中退一步，寻找跨模块反复出现的设计思想、真实依赖和相互作用，形成少量更清楚的问题。

用户关心的相似性类似：在不同技术里辨认出相同的计算组织方式。请允许提出直觉性的联系，再把它具体化为“哪些对象、操作、条件相似”，并检查这种联系在哪里失效。

本轮的成果应是：
1. 2–3 个有解释力、适合继续讨论的问题；证据不足时可以更少。
2. 每个问题对应的原文依据、共同机制、关键差别、具体例子和最强反对意见。
3. 一条建议优先继续的讨论线，以及保留的分歧。
不需要列举很多方向，不需要提出完整系统，不把本轮结果包装成已经确认的新研究缺口。

二、材料与证据范围

阅读项目中的全部 7 份 Markdown，重点理解前半部分的概述：
Overview.md、workflows.md、memory.md、tools.md、orchestration.md、hooks.md、verification.md。
当前副本可能带有数字前缀，请按名称和内容识别。

核心证据只取自：
Dong 等，Towards Long-Horizon Agents: A Survey，第 4 章 Harness。
当前项目 PDF 的这一章在 pp.20–37；p.37 下半进入第 5 章。若其他副本页码变化，以章节标题为准。

重要边界：
- Markdown 后半部分包含原论文精读和综述外补读，不将这些内容当成本轮机制、实验或反例的证据。
- 即使 Markdown 前半部分写得很确定，也要区分综述原有论述与笔记作者的归纳。
- 第 4 章本身提到的训练、路由学习、技能演化等可以讨论；不延伸阅读第 5 章，不追读参考论文。
- 不联网，不用外部论文、项目或既有记忆补齐未被综述说明的实现。
- 可用依赖、反馈、封装等一般概念帮助解释，但不能因此断言方法等价。
- 综述可能有不够严格的分类。本轮可以指出文本内的重叠或张力，不能凭记忆裁定某篇原论文的真实实现。
- 找不到原文支持时，标记“本轮材料不足”；不要编造页码、引文或实验。
- 不修改现有知识库主题页，不把候选问题直接写成知识库事实。本轮只交付独立讨论记录。

所有论断使用以下三种身份：
[原文]：综述第 4 章明确表达的内容；附 §小节和 PDF 页码。
[归纳]：根据两处以上原文形成的跨节解释。
[假设]：尚待检验的融合方式、潜在冲突、收益或研究问题。
原文锚点优先用简短转述，不大段摘抄。

三、组织方式

采用 1 位主 Agent + 3 位子 Agent。每位子 Agent 都应阅读全部六模块的概述，并核读第 4 章相关内容；按观察视角分工，不按章节分工。

Agent A：依赖、状态与恢复
- 谁产生什么状态或前提，谁消费它？
- 哪些依赖是数据/状态依赖，哪些决定控制、证据有效性或执行条件？
- 上游改变后，下游哪些结果应失效？哪些工作可以保留？
- 压缩、交接、技能复用会怎样隐藏这些关系？
- 不把存在依赖等同于强耦合，也不把所有依赖都解释为必须串行。

Agent B：辅助判断、控制与资源分配
- 监测器、验证器、路由器、规划者分别看什么、判断什么、能改变什么？
- 评价信号如何影响继续、分支、重规划、换执行者、阻止或结束？
- 什么时候缺的是证据，什么时候缺的是候选、判断或执行能力？
- 哪些信息或计算可以共享？哪些目标、约束和控制权限必须分别保留？
- 不把 Hook、Verifier、Planner 都叫“裁判”就视为完成分析。

Agent C：抽象、复用与演化
- 上下文压缩、经验记忆、技能封装、子任务委派，分别减少哪种重复或局部复杂性？
- 它们隐藏了什么细节，又必须保留什么适用条件与证据？
- 轨迹如何变成摘要、经验、技能、检查清单或编排改动？
- 区分状态更新、库内容更新、运行时策略选择和模型参数训练。
- 哪些更新彼此相容？哪些更新会改变其他模块依赖的状态或判据？

主 Agent：
- 独立核对最终保留候选的原文。
- 对重复提案去重，指出已有明确关系，区分解释性总结与新增问题。
- 主持交叉质疑，保留有意义的分歧。
- 不因三个 Agent 达成一致，就提升结论的证据等级。

若运行环境不足以同时启动三个子 Agent，可分批完成。说明实际采用的组织方式，不宣称发生了并不存在的并行或独立讨论。

四、讨论种子

以下是起点，不是必须得出的结论，也不是限制探索范围的目录。

种子 1：依赖与局部恢复
问题：前提改变后，如何知道哪些后续结果需要重做、哪些仍成立？
锚点：§4.1.2 p.21 的计划更新/作废；§4.2.2 p.26 的记忆维护；§4.3.3 pp.28–29 的技能关系与局部修复；§4.5.3 p.34 的错误定位与定向回退。
注意：这些机制的存在不等于综述已给出统一的跨模块失效传播方案。

种子 2：相同运行证据与不同处置
问题：同一段反复失败的轨迹，何时该重规划、换执行者、补证据或阻止继续？
锚点：§4.1.2–4.1.3 pp.21–23；§4.4.3 p.30；§4.5.3 pp.33–34；§4.6.2 p.36。
注意：共同输入不推出相同目标；分数本身不拥有执行权；增加判断调用、使用另一套权重、专门训练三个问题要分开。

种子 3：多个更新环路怎样共同演化
问题：技能或编排更新后，哪些旧监测判据仍有效？该如何安排不同对象的更新顺序？
锚点：§4.2.2 p.26；§4.3.3 pp.28–29；§4.4.3 p.30；§4.5.3 p.34。
注意：经验记忆转为技能、技能库与编排的外化演化，综述已经明确提到。仅说“共享轨迹”还不构成新问题。共享记录不等于共享标签，也不等于需要联合训练。

种子 4：隐藏细节时保留什么
问题：把复杂过程压成摘要、封装成技能或交给子 Agent 后，哪些条件必须继续对主 Agent 可见？
锚点：§4.2.1 p.24；§4.3.3 p.28；§4.4.1 pp.29–30；§4.6.2 p.36。
注意：压缩改变可见状态，技能可能改变动作粒度，委派改变执行责任；三者不能简单等同。共同设计压力可能在于“主循环看到什么、边界上承担什么责任”。

种子 5：下一份额外工作应花在哪里
问题：下一步应检索、比较候选、增加验证还是换执行者？这种选择与后续依赖范围有何关系？
锚点：§4.1.3 pp.22–23；§4.2.1 p.24；§4.3.2 pp.27–28；§4.4.3 p.30；§4.6.3 pp.36–37。
注意：强制约束不应被当成可随意跳过的开销；token、延迟、工具额度和上下文容量也不能假定自由兑换。

五、执行过程

第 1 轮：独立提出联系
各子 Agent 在看到其他人的提案前先完成初稿。每人最多提交 2 张候选卡，不必填满名额。先尝试寻找至少一条不直接复述五个种子的联系；若没有更强的联系，可明确说没有，不为新奇强行类比。

每张候选卡回答：
1. 一句话直觉：普通读者应能懂。
2. 至少两个不同 §4 子节的证据锚点：写出小节、页码、支持的具体内容。
3. 机制映射：具体是哪种输入、操作、产物、条件或反馈相似？
4. 关键差别：什么不能合并或相互替代？
5. 一个最小思想实验：只改变一个条件，说明它会影响哪项设计选择。
6. 最强反例：什么时候这条相似性没有用，甚至误导？
7. 一个收窄后的讨论问题。
8. 标注哪些属于原文、归纳和假设。

不要求每张卡覆盖全部六模块；连接 2–3 个模块且解释具体，往往已经足够。
不要停留在“都需要状态”“都使用反馈”“都提升效率”等几乎适用于所有软件的句子。
不接受“把 A+B+C 融合”作为充分说明，必须说共享什么、改变什么、为什么可能值得。

第 2 轮：交叉质疑并修订
主 Agent 收齐独立提案后再共享，安排 A 审 B、B 审 C、C 审 A。
每位评议者只挑最有讨论价值的 1–2 张卡，提出一个有力反例和一个改写建议，不写泛泛的赞同或风险清单。

评议需回答：
- 是原文已经明确说出的关系，还是需要进一步论证的跨节推断？
- 相似之处具体落在哪个操作？换个术语后是否仍只是空泛描述？
- 能否构造一种条件，让两个看似相似的模块需要相反处置？
- 若建议融合，共享的是记录、表示、模型参数、目标还是控制权限？
- 若声称冲突，具体是哪两个动作、目标或更新彼此影响？是否也存在相容的配置？
- 这条联系能否指导一个实际设计取舍？如果不能，应降级为解释性类比。

提案者据此明确选择：保留、收窄、改写或撤回，并说明改变了哪条主张。
有争议时回查原文。不要用反复投票解决证据不足。
默认只完成以上两轮；若一个关键原文分歧能通过一次定向核对解决，可追加该核对，然后收束。

共同思想实验可使用“文献整理 Agent”：
读取原文 → 提取条件 → 形成比较结论 → 保存笔记 → 复用经验。
可以分别改变一项条件，例如上游结论修正、摘要漏掉适用范围、技能换版本、失败来自临时故障或解释冲突。
明确说明这是教学情境，不是论文报告的实验结果。

六、综合与筛选

按以下问题判断候选，不虚构数值评分：
- 它是否忠实于本轮材料？
- 它是否连接了不同职责，而非重复同一机制的两个名称？
- 它是否比“都有反馈/状态”多解释了一件事？
- 它能否改变一种具体设计选择？
- 它与长程任务的依赖、状态持续、反馈时点或经验复用有什么关系？
- 它的边界能否说清？

最终最多保留 3 个问题；允许保留 1 个关键分歧。另用短表列出 1–2 个被降级或撤回的联想及原因。
不强行达成共识，不强行提出一套统一架构。
不以没有在综述中看到某方法为理由宣称领域无人研究。

七、最终交付

用中文交付一份约 2500–3500 字的讨论记录，不逐字输出讨论过程。格式如下：

A. 对本轮问题的一段重新表述。
B. 一张跨模块关系表：共同思路、涉及模块、关键差别、原文位置。
C. 最多 3 张最终问题卡，每张包含：
   - 一句话问题；
   - 原文已支持什么；
   - 跨节归纳是什么；
   - 最小思想实验；
   - 最强反对意见；
   - 经质疑后保留的主张；
   - 如果继续思考，下一步最需要澄清什么。
D. 一张短表：撤回或降级的联想、原因。
E. 优先继续哪一个问题，以及选择理由。
F. 简短列出各 Agent 的独立贡献和讨论后发生的修正。

若画图，只画有具体语义的关系：边标明传递何种状态、反馈或控制；不要把六模块画成无差别的全连接图。
后续澄清优先仍采用思想实验或回查本综述，不在本轮启动补读论文、自动抓取或实验。

请现在开始阅读、独立提案、交叉质疑、修订和综合。最终回答应让我更容易选择下一步值得思考的问题。
