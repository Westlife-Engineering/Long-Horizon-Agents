# Ingest 清单

规则入口：[[AGENTS#4. Ingest：读取并整合新来源|AGENTS · Ingest]]。由用户提交来源或已授权的 [[workflows/autoresearch|Auto Research]] 轮次触发。本清单定义实际操作，不代表已有后台任务；阅读与分析直接按本库规则执行，不依赖其他论文阅读 skills。

## 从原文到知识更新

1. 读 [[wiki/index|索引]]、[[wiki/log|最近操作]]、相关主题与论文页；按标题、作者、DOI/arXiv 和版本查重。并发任务先取得全库唯一的来源 ID、Raw 目标路径与论文页所有权；同论文跨方向复用，不重复摄入。
2. 核实来源身份，归档原件到 `raw/`，比对归档前后 SHA-256。在线获取须记录原始 URL、访问日期和版本；网页知识须保存可回查的原始快照。新版另存并关联旧版，不覆盖已存原件。仅筛选的候选不创建论文页、不计已读。
3. 实际读正文、相关方法/实验/局限及支撑关键结论的图表、公式与附录；记录读到和未读的范围。只读摘要可用于筛选，不能完成方法与证据分析；作者转述他人结果仍属于转述。提取文本只是定位辅助，重要图表与公式须看原页。
4. 更新唯一论文页：来源 ID、身份、原始文件、SHA-256、读取日期与范围、下表涉及的核心理解、证据定位、限制及实际整合主题。按论文类型组织自然的解释，不机械堆满字段；未报告的信息写“原文未报告”，尚未查到的信息写“本次未核读/未确认”。
5. 写明它怎样支持、修订、限制或挑战已有判断，也允许“补充适用条件，暂不改变主要判断”。把有用内容整合进已有主题，维护双向链接；只在内容需要时拆页。并行时按 [[workflows/autoresearch#派发与共享写入|共享写入协议]] 取得写入时段，再修改主题、索引及日志。
6. 按 [[workflows/presentation|阅读表达清单]] 把机制图或对照表放在对应解释旁，保留必要论证与证据；不另建 Canvas 或平行正文。同步索引中的页面、来源数与实际阅读状态。
7. 做局部 [[workflows/lint|Lint]]，返回交付包与简短日志草稿，未完成项如实标记；主 Agent 验收失败则回到负责该论文的 subagent 修订。实质验收通过后，由原负责人在共享写入时段追加一条 `ingest` 日志、更新完成状态并返回收尾确认；同一来源的修补和检查不拆条。非委派的单人摄入完成相同检查后直接收尾。

## 单篇分析要回答什么

这是研究检查表，不要求每项单独成为标题。每个重要判断紧邻原文链接、PDF 页码与章节，必要时附图、表或公式号；沿用“原文陈述 / 综述转述（原论文未读） / 本库推断 / 待检验问题”四种证据身份。

| 分析问题 | 应提取的研究信息 |
| --- | --- |
| 具体困难与“长在哪里” | 任务、失败现象、跨步骤依赖；上下文内执行、跨上下文状态或跨任务经验的压力。论文未采用 H1–H3 时，将映射标为本库分析，不替作者宣称层级。 |
| 实际改变了什么 | 输入、输出、状态、触发条件、信息流、动作和反馈；改变模型、harness、数据/环境还是评测。多处同时改变时指出归因边界。 |
| 为什么可能有效 | 作者的机制解释、明说的前提、由本库推断的前提；例如反馈可靠性、可重试性、额外调用或完整历史的依赖。 |
| 证据支持到哪里 | 任务/数据划分、模型、harness、训练与推理预算、指标、基线和消融；把作者主张与直接支持它的实验分开。关键数字只在有比较价值时摘录，并保留条件。 |
| 与最接近工作有何差异 | 作者声称的贡献与本库核验后的比较分开；未读对方原文时，只能记作者比较或待核验判断，不能宣布优劣或新颖性。 |
| 什么尚未解释 | 缺失的消融、未测条件、失败案例、替代解释；“没测试”不等于“方法无效”，作者 Limitations 也不等于完整的领域缺口。 |
| 怎样改变本库 | 对应哪个已有判断或问题，属于支持、修订、限制、冲突还是补充；冲突先核对任务、模型、预算与术语。没有实质变化也如实写。 |
| 下一条值得获得的证据 | 最有价值的补读或核查及其理由；可以没有新问题。候选问题进入 [[workflows/query\|综合]] 和 [[workflows/brainstorm\|审查]]，不在单篇阅读时直接确认为创新点。 |

论文类型影响重点：**综述**记录地图、分类、范围与主题落点；**方法论文**解释机制和对照证据；**评测论文**检查测量对象、任务构造、成功判据与混杂因素；**分析论文**检查假设、解释与证据如何对应。理论主张区分假设、证明结论与经验验证，不硬套实验模板。

## Subagent 交付与验收

每篇论文由同模型 subagent 负责到底，交付包含：

- **身份与读取：**唯一来源 ID/论文页、原件与哈希、实际阅读范围、未读部分和获取障碍。
- **知识变化：**新增的核心理解、改变的原判断及证据定位；实际修改的主题与双向链接。
- **证据边界：**作者主张、实验支持、推断和疑问；最关键的未确认项。若结果可能改变选题判断，标出需要独立回读的具体原页。
- **维护结果：**修改文件与共享写入已完成状态、局部 Lint、索引/来源状态、待追加的日志草稿；验收收尾后返回正式日志位置。分别报告结构检查、内容核对和 Obsidian 实测范围。

论文页写好但主题/索引尚未更新时，状态为“已读待整合”；整合后待主 Agent 检查时为“待验收”。只有原件、阅读、主题整合、维护检查、主 Agent 验收及日志收尾都完成后，委派任务才可报告摄入完成。Obsidian 不可用时可交付知识结果，但须单列应用验收未测，不能宣称全部验收通过。读取失败不创建看似已读的论文页，保留已获取原件并在轮次记录中说明阻塞。
