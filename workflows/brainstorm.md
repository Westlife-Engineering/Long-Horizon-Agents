# Brainstorm：围绕共同证据独立提出和审查问题

规则入口：[[AGENTS#Auto Research 与多 Agent 协作|AGENTS · 多 Agent 协作]]。本流程由 [[workflows/query|Query]] 或 [[workflows/autoresearch|Auto Research]] 调用。目标是形成可继续调查的问题、消除误解或关闭不成立的构思，允许零个候选 idea。

## 先完成证据准备

先明确本轮采用跨论文比较与查证，还是下节的综述内讨论。跨论文模式完成最基本的跨论文比较；综述内模式固定允许章节与跨节锚点。两者均固定同一份证据清单：

- 本轮问题、范围、预算，以及论文 ID、版本/哈希、实际阅读范围、唯一论文页和原始页定位。
- 当前已知的机制、前提、评测条件、冲突与未知；明确哪些仅由综述转述。不能只给选中的“正面”结果而隐去相关反例。
- 本轮要检验的关系及已排除的问题，区分原文陈述、本库推断和待检验问题。

证据清单引用正式来源页与Raw，不复制平行正文；递归使用当前分类路径，目录与材料分流按[[workflows/structure|目录规则]]。临时证据包标记日期/版本和页面内容版本，留获准临时区，不放Raw；需长期保留的简短审查范围及版本记录归轮次维护页。讨论期间相关页实质更新时，先登记并同步共同增量。没有独立原文证据时只能生成补读问题，不能声称研究缺口。

## 角色和两轮流程

### 综述内讨论与组会交付

用户限定只读一份综述时，允许从不同小节提出机制联系，不强制跨论文比较、查新或补读。不联网、不追引文和不读其他章节等限制在本轮约定中写明；以下检索与 Ingest 步骤仅在本轮明确授权时启用。不能以综述没有提到某方法断言领域空白。

组会模式在 `组会/<准备日期>-<主题>/README.md` 固定实际材料、角色、预算、写入范围和交付；当前 Harness 轮次采用依赖/恢复、判断/控制、抽象/演化三个观察视角，同模型首稿隔离，每人最多两张候选卡，A 审 B、B 审 C、C 审 A，两轮合计收束，最多追加一次关键原文核对。具体种子保留在本轮输入提示词，不作为所有任务的预定答案。

论断可用 `[原文]`、`[归纳]`、`[假设]` 标示：原文指综述明述，涉及所引研究时仍写“综述转述”，展望仍是作者观点；归纳须连接至少两个不同小节并写出推理；假设指待检验的融合、冲突、收益或思想实验。概述笔记也须逐条回证，前半部分不是自动合格的证据白名单。

Insight 验收看具体操作、成立条件和设计取舍：改变一个前提后，何种选择应改变，最强反例能推翻什么。泛泛的状态/反馈类比、仅说融合多个模块、同模型共识都不足以增加证据。允许更少或零个候选，不预设统一架构。

完整讨论先在组会目录定稿，结构化首稿及关键修订保留为形成过程；主 Agent 回读最终主张的原页，再将可独立解释的阶段性理解写入相关主题页。正式成果保留原文定位、推理与边界，不以讨论页代替证据；未经核查的候选不自动入库。主题页与组会记录互链；有必要的关系图按阅读表达流程制作。文件归属和清理见 [[workflows/structure#组会工作区与成果沉淀|组会工作区]]。

### 通用协作纪律

主 Agent 组织并验收；模块负责人可以承担具体调度、去重和整合。参与 subagent 使用主 Agent 同一模型，首轮不接收其他参与者的初稿；只共享证据和规则。“独立”表示初稿互不影响，不表示模型偏差独立。

| 角色 | 独立判断的重点 | 必须交付 |
| --- | --- | --- |
| 机制与边界审查 | 解释依赖什么前提，证据是否真正识别了该机制，替代解释是什么 | 指向原页的支持/质疑、最需要核查的前提；也可提出候选问题 |
| 跨论文构思 | 同一问题下的机制差异、共同限制、条件变化或可迁移结构 | 从具体观察推导的候选问题、价值和区分解释所需证据；不只说“结合 A 与 B” |
| 反证与查新 | 初稿阶段独立找已有覆盖、反例与术语差异；互评阶段攻击候选问题最强版本 | 最接近工作、相同/不同之处、关闭理由或仍未确认项；无检索时明确待查新 |

1. **首轮独立分析。**三类职责各自给出简短判断，最多保留 3 个有依据的问题，也可以不给。先收齐独立结果，再交换意见；不预先发主 Agent 的偏好答案。
2. **交换与核查。**模块负责人合并重复项，保留分歧，为每条关键质疑指定原页核查、机制近义词检索或相关工作补读。已有原页可直接回读；新来源按 Ingest 纳入。不能用措辞辩论替代获取缺少的证据。
3. **第二轮修订与结案。**把同一批补充证据发给参与者，要求说明原判断如何变化、问题是继续追踪、收窄、被覆盖还是暂缓。既没有新增证据，也没有预算内可执行的具体核查时提前结束；仅暂缺新证据而有明确核查任务时，先按剩余预算执行。达到轮数或阅读上限即收束，不为达成一致追加轮次。

两轮是每批候选的总上限，包含模块内与必要的跨模块修订，不因新增角色重新计算。跨模块问题尽量合入第二轮；若内部已用完两轮，跨模块只整合已有判断，新增争议留待下一轮，不再追加补读。范围更大时按预先约定的方向批次运行。人员名额不足可顺序运行隔离的首轮任务，不能把读过他人答案后的任务说成独立首轮。

主 Agent/模块负责人不以多数票、角色头衔或模型打分确认新颖性；同篇来源被多人引用仍只算一个来源。决定性主张有疑点时，派未参与该主张写作的审查者核对原页，提供“支持 / 部分支持 / 不支持 / 无法判断”及具体理由。

## 候选问题的最小内容

先区分三类：**理解缺口**需要解释或回读；**本库证据缺口**需要补充材料；**限定检索范围内的候选研究缺口**仍需要相关工作差异与价值论证。它们不取代原有四种证据身份，也不把“本文没做”升级为“领域没人做”。

有长期价值的问题写入最相关的现有主题页，使用稳定的页内标题/问题标识；成熟后才拆页。每项保留：

| 字段 | 要回答什么 |
| --- | --- |
| 问题和适用范围 | 哪个具体任务、条件或机制有疑问？为什么值得弄清？ |
| 引出问题的证据 | 哪些已读论文的哪些观察/原页支持提出它？综述转述单独标明。 |
| 候选解释或方法 | 从观察到解释的推理是什么？哪些步骤仅属本库推断？ |
| 最接近工作与剩余区别 | 已核读工作的机制、条件、任务和证据覆盖了多少？未核读的只是线索。 |
| 最强反对意见 | 哪条反例、已有覆盖、归因问题或前提失效会推翻它？还缺什么核查？ |
| 下一条证据 | 下一步应读什么、查什么，或哪类消融/失败案例能区分解释；此处不自动启动实验。 |
| 状态与变化理由 | 待澄清、待补读、待查新、继续追踪、已有工作覆盖或暂缓；说明证据导致的状态变化。 |

被已有工作覆盖的问题保留简短关闭理由与证据，不抹掉后再重复提出。“继续追踪”仅表示值得进一步调查，不表示创新性、可行性或最终选题已确认。

## 查新和反证的记录边界

记录检索日期、渠道、实际查询词/近义词、范围、最相关结果、全文可用性以及哪些原文已经核读。检索应围绕机制、任务和失败现象，不能只搜 Long-Horizon Agents 这个标签。

搜索结果/摘要仅作线索；用来支持关闭或保留候选的关键判断须核读对应原文、保存来源并给定位。拿不到正文时保留不确定性，不把查不到当成不存在。检索过程的长输出放临时区，主题页仅保留足以回查的短记录、关键结果与证据边界。

结论限定为“截至本轮检索，在这些已核查工作和条件中尚未找到充分回答”，不写“没人做过”。若只检索了综述引用，明确这不是覆盖后续文献的查新。补读达到上限时留下待核查项并停止，不循环扩张引用链。

## 最终写回与交付

经核查的单篇理解回唯一来源页；跨论文关系、候选问题和关闭理由回相关方向主题，Overview只保留导航与必要摘要，已有独立内容时可搬移拆页；跨模块问题只选一个主要落点，另一模块链接过去。角色交付、调度和检查点归维护记录或临时区，不混成另一份论文正文。

由获分配共享写入时段的负责人完成修改，主 Agent 验收：核心判断能否回查原页，比较是否解释机制/条件差异，疑问是否转成明确核查，产物是否帮助用户选择亲读内容。执行 [[workflows/lint|Lint]] 和受影响的 [[workflows/presentation|阅读表达检查]]，有实质综合或重要问题时合并记一条 `query` 日志。不保存所有 Agent 对话，也不按角色数量记日志。

讨论结束且结论、关闭理由、查新范围及必要版本信息已归位后，按[[workflows/structure#保留标准与临时文件清理|清理规则]]移除全量对话、重复首稿/互评、临时证据包和搜索长输出；组会模式保留获约定的结构化提案与关键修订记录。未决且确需接续时只保留最小恢复集。文件被列进临时清单不构成永久保存理由。
