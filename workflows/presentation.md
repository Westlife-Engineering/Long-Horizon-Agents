# 阅读表达清单

规则入口：[[AGENTS#阅读与视觉表达|AGENTS · 阅读与视觉表达]]。本清单由 Ingest / Query / Lint 复用，不另建知识治理层。

## 设计与同步

目录与导航先按[[workflows/structure|目录组织规则]]检查：文件树能区分综述、模块和子方向，原文与唯一来源页有对应路径；Overview应让读者进入具体主题，而非迫使其在多万字正文末尾找论文清单。目录分类不替代跨主题链接，索引链接也不替代可浏览的物理目录。

1. 先确定读者要理解的问题、最关键的判断和容易混淆的关系，再按 [[AGENTS#阅读与视觉表达|表达分工]] 选择主表达。Mermaid 与 Excalidraw 以空间布局是否承担解释作用区分，不设节点数量门槛；拥挤时先考虑分组或拆图。只有选定 Excalidraw，才继续读取下方项目适配及其引用的 skill。
2. 第一眼能看到问题、判断、证据身份和必要边界；解释图不替代原文证据，不将所有限定隐藏在折叠块中。箭头明确表示顺序、依赖、信息传递、控制或反馈，不把并列概念画成因果；同色不作为唯一含义提示。
3. 图紧邻它解释的问题，用结构表达反馈、分支或区别；文字补充例子、原因、推导与限制。不要把旧正文保留原样，再在前面追加一套图解。检查图和文字是否只是重复；没有额外解释价值时删冗余文字或省去图，不损失证据与论证。
4. 完整内容归唯一相关知识页；内容变化后核对同页图、图片、导航及实际存在的关联展示，展示变化后反向核对主张、来源与范围。更改标题或块 ID 前查找入链并同步修复，避免平行正文。
5. 默认通过文件与绘图工具生成内容，已安装的 Excalidraw 插件作为可选编辑入口，不自动增加插件或修改设置。最终图源与图片存 Wiki 资产目录，保留可搜索的必要文字说明、来源及示意性质；中间产物存系统临时目录。独立 HTML 仅用于明确的浏览器分享或额外交互需求，不取代主笔记，并标明同步状态。
6. 视图暂未同步时标明状态，退出主入口或直接提醒。浏览器旧快照不作为最新知识视图。图解笔记已选为默认入口；其他主题在后续阅读、查询或更新时按内容逐步改进，不批量套模板。全局关系图的美观、节点或边的数量不作为知识质量指标。

## Excalidraw 项目适配（选用时读取）

读取并使用通用 `$excalidraw-diagrams` skill，按当前会话的技能目录定位 `SKILL.md`；本机位置为 `C:/Users/ZENGZX/.codex/skills/excalidraw-diagrams/SKILL.md`。路径失效时先按技能名定位；仍不可用则说明缺失，不声称已执行 skill。通用 skill 负责布局、批量绘制、绑定、渲染与视觉修订；此处仅覆盖项目差异，不复制或改写通用 skill。运行接口按需读取该 skill 的 runtime 参考。

- **证据与样式**：区分原图摘录、依据原文重绘、本库综合与教学类比；图旁保留来源 ID、PDF 页码及章节，图内保留理解所需的关键限定。正文中文，必要术语保留英文；按 Obsidian 正文宽度设计，少量语义色，颜色之外仍有文字或形状区分。精确标签、箭头和公式不交给文生图；组合插画时说明位图部分不可按节点编辑。
- **目录与保留**：有实际图需求时才创建 `wiki/assets/diagrams/<diagram-id>/`，使用稳定短名称。原生图源与 PNG 放同一图目录，SVG 仅在有矢量使用需求时保留。临时导入 JSON、草稿、截图及生成脚本放系统临时目录（任务另有授权临时区时遵从），不照搬通用 skill 的 `work/` 或默认永久保存生成器；不预建空目录。
- **绘图与编辑源**：沿用通用 skill 的 MCP 优先、CLI 回退、批量绘制与渲染检查流程；默认保存标准 `.excalidraw` 作为长期可编辑源，不将它视为临时文件。修订先读当前源并保护手动编辑，不用旧脚本覆盖。插件 `.excalidraw.md` 仅在用户要求插件内编辑／原生嵌入，或已有目标图使用此格式时按需处理，不能只改扩展名；不维护两份各自修改的图源。图源是表达资产，不计学术来源或独立知识页。
- **嵌入与导出**：笔记默认嵌入同场景 PNG，并链接 `.excalidraw` 图源；图片路径相对目标笔记计算，只引用实际存在的文件。图源修改后同步重导出，不假设插件已配置自动导出。插件原生嵌入是可选要求，不作为普通绘图交付条件。
- **验收与桌面边界**：通过工具渲染并实际查看最终图片，检查源文件结构与笔记引用；此流程不依赖 computer use 或打开 Obsidian。只有用户明确授权桌面操作时，才进行下方 Obsidian 应用实测；没有授权时完成文件与图片检查，并如实标记“Obsidian 内显示未测”，不将可选插件转换列为未完成任务。渲染失败则保留可恢复图源并说明视觉验收未完成，不以 JSON 合法代替看图。

## 检查与交付

- **文件**：wikilink、标题/块、PDF页码有效；表格别名转义；代码围栏和Callout完整。目录迁移后检查文件树、镜像归属与来源跳转；旧日志分别按已登记迁移或历史撤下项处理，不能混淆移动和删除。
- **内容**：判断、证据身份、关系方向、必要限定和正文一致；图不能把综述转述升级为直接证据；学术判断变化仍回读原文。
- **应用**：computer use 操作 Obsidian 须有用户明确授权；未获授权时不占用桌面，完成可执行的文件／渲染检查并标注应用未测。获授权后，按变更范围检查笔记、代表性来源跳转、Mermaid、公式、表格、折叠及实际阅读布局；新增引用机制时，用可恢复的临时标记检查更新跟随并恢复。应用实测与绘图产物检查分别报告。
- **可读性**：在正常窗口和窄分栏检查截断、缩放与连线辨识；涉及配色时检查深浅主题。还要检查读者是否必须在图与重复长文之间来回寻找相同解释。记录实际条件，未测条件如实列出，不将某一主题/宽度通过推广到全部设备。
- **结果**：分别报告内容/结构检查、应用实测及待用户比较项。应用不可用时继续完成可完成的工作，标记未测范围；不能宣称展示验收全部通过。

只对本次变化影响的范围检查。与知识更新一起进行的检查并入同一条操作日志；普通解释和微小排版不额外记账。入口选择、布局或工具选择可随实际阅读反馈演化。

视觉核对结束后，删除可从原件再生成的临时截图、渲染图片和提取文本；正式引用的表达资产保留。保存网页HTML不等于保存截图，二者都须满足[[workflows/structure#保留标准与临时文件清理|保留标准]]，不因浏览过就入库。
