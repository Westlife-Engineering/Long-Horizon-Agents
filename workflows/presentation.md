# 阅读表达清单

规则入口：[[AGENTS#阅读与视觉表达|AGENTS · 阅读与视觉表达]]。本清单由 Ingest / Query / Lint 复用，不另建知识治理层。

## 设计与同步

目录与导航先按[[workflows/structure|目录组织规则]]检查：文件树能区分综述、模块和子方向，原文与唯一来源页有对应路径；Overview应让读者进入具体主题，而非迫使其在多万字正文末尾找论文清单。目录分类不替代跨主题链接，索引链接也不替代可浏览的物理目录。

1. 先确定读者要理解的问题、最关键的判断和容易混淆的关系，再决定解释顺序。默认维护同一份图解笔记：过程与反馈考虑 Mermaid，概念差异考虑对照表，详细论证保留正文或折叠 Callout。Canvas 暂不保留或新建，除非用户明确要求重新试用。
2. 第一眼能看到问题、判断、证据身份和必要边界；解释图不替代原文证据，不将所有限定隐藏在折叠块中。每条箭头有明确语义；同色不作为唯一含义提示。
3. 图紧邻它解释的问题，用结构表达反馈、分支或区别；文字补充例子、原因、推导与限制。不要把旧正文保留原样，再在前面追加一套图解。检查图和文字是否只是重复；没有额外解释价值时删冗余文字或省去图，不损失证据与论证。
4. 完整内容归唯一相关知识页；内容变化后核对同页图、图片、导航及实际存在的关联展示，展示变化后反向核对主张、来源与范围。更改标题或块 ID 前查找入链并同步修复，避免平行正文。
5. 原生能力不足时才讨论 CSS、插件或外部网页。新建最终图片时保存至实际需要的 Wiki 资产目录，给出文字等价说明、来源及示意性质；中间产物存系统临时目录。独立 HTML 须明确用途和同步状态。
6. 视图暂未同步时标明状态，退出主入口或直接提醒。浏览器旧快照不作为最新知识视图。图解笔记已选为默认入口；其他主题在后续阅读、查询或更新时按内容逐步改进，不批量套模板。全局关系图的美观、节点或边的数量不作为知识质量指标。

## 检查与交付

- **文件**：wikilink、标题/块、PDF页码有效；表格别名转义；代码围栏和Callout完整。目录迁移后检查文件树、镜像归属与来源跳转；旧日志分别按已登记迁移或历史撤下项处理，不能混淆移动和删除。
- **内容**：判断、证据身份、关系方向、必要限定和正文一致；图不能把综述转述升级为直接证据；学术判断变化仍回读原文。
- **应用**：在 Obsidian 打开索引、修改的笔记和代表性 PDF 来源链接。检查 Mermaid、公式、表格、折叠操作、导航与实际阅读布局。新增引用机制时，用可恢复的临时标记检查更新跟随并恢复。
- **可读性**：在正常窗口和窄分栏检查截断、缩放与连线辨识；涉及配色时检查深浅主题。还要检查读者是否必须在图与重复长文之间来回寻找相同解释。记录实际条件，未测条件如实列出，不将某一主题/宽度通过推广到全部设备。
- **结果**：分别报告内容/结构检查、应用实测及待用户比较项。应用不可用时继续完成可完成的工作，标记未测范围；不能宣称展示验收全部通过。

只对本次变化影响的范围检查。与知识更新一起进行的检查并入同一条操作日志；普通解释和微小排版不额外记账。入口选择、布局或工具选择可随实际阅读反馈演化。
