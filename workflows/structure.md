# 目录组织与迁移

规则入口：[[AGENTS#1. 三层边界|AGENTS · 三层边界]]。本文件规定材料归属、论文分类及迁移验收；Ingest、Query、Auto Research、Lint共同使用，不能由各任务另定一套路径。

**2026-10-25修订状态：仅更新规则，尚未执行目录迁移。** 以下是目标结构，不是对当前目录已经整理完成的声明。历史平铺文件由后续整理任务统一迁移；本次不移动资料、不改知识页或日志。未来任务必须先识别迁移状态，不能因旧路径存在就另建一份新页。

## 材料按类型归档

| 内容 | 目标位置 | 边界 |
| --- | --- | --- |
| 综述正文PDF | `raw/surveys/<题名>.pdf` | 综述单列，不混入方法、系统、评测、分析论文目录 |
| 其他论文正文PDF | `raw/papers/<模块>/<主方向>/<简称>.pdf` | 本目录只放论文正文PDF；原始渠道只有HTML时先按网页快照保存，不伪造原始PDF |
| 作者补充材料 | `raw/supplements/<来源ID>-<简称>/` | 附加PDF、作者发布的附录文件等；正文内已有附录不另拆。可区分版本，归属原论文，不另计来源 |
| 官方代码与仓库元数据快照 | `raw/code/<来源ID>-<简称>/<commit>/` | 保留所取源码的相对路径；原始API返回的commit/tree/repo元数据可放该快照的`_metadata/`；明确是否完整仓库、读取范围及完整commit |
| 网页原件及身份页面 | `raw/web/<来源ID>-<简称>/` | 保存原始HTML/响应及版本或访问日期；对应论文的身份快照不增加论文数。独立网页来源用自己的来源登记 |
| 理念文章等 | `raw/articles/` | 保留原有用途，不因研究扩张变成临时杂物目录 |
| 综述知识页 | `wiki/surveys/<题名>.md` | `type: survey`；领域地图、阅读范围和主题落点 |
| 其他论文知识页 | `wiki/papers/<模块>/<主方向>/<简称>.md` | `type: paper`；唯一来源页，分析重点仍按方法/系统/评测/理论等类型调整 |
| 主题理解与综合 | `wiki/<模块>/`下的主题页 | 面向阅读的问题、机制、比较和证据，不承担完整任务队列 |

位置由**内容和出处**决定。官方README、源代码及原始API响应可以是Raw证据；Agent生成的下载清单、哈希汇总、审查报告、handoff、检索长输出、运行日志和脚本不是原始来源，不能因它们关联某篇论文就放进Raw。URL、版本、哈希等归档登记放唯一来源页或维护记录，不修改原件来补说明。

提取文本、渲染截图、未定稿讨论及临时脚本使用会话允许的临时区；用户限定项目内工作时，使用被Git忽略的`.research-tmp/`，不转存到Raw或知识页目录。确需长期保留的轮次约定、恢复点和Git检查点放`maintenance/research/<轮次>.md`；迁移映射放`maintenance/migrations/<日期>-<操作>.md`。这些是维护记录，不计学术来源或Wiki知识页，不保存全部聊天。只有实际内容需要时才建文件/目录。

## 一个主归属，多个主题关系

论文与笔记使用相同的模块、方向和文件简称，相对路径镜像；综述两侧同样对应。简称确认后尽量稳定，整理目录不顺便批量改标题。来源ID、标题和DOI/arXiv用于身份判断，目录只是主归属，移动不能改变来源ID。

普通论文页增加`primary_direction`（例如`harness/memory`）；有实际交叉关系时再加列表字段`related_directions`。综述不强制分配技术主方向。主归属按主要贡献与本库使用目的判断，不能只因最先在哪个队列读到就永久归类；多方向工作选一个主落点并记录理由，其他方向用链接及元数据关联，不复制PDF、论文页或用软链接制造多份入口。

确有不适配现有分类的材料时，补充有内容、有理由的类别并同步本词表，不强塞，也不生成长期堆积的“其他/未分类”目录。多领域综述仍归综述目录；一般方法论文不会因带Related Work而变成综述。

创建路径一律从Vault根目录解析，先验证解析后的绝对路径在本项目内。Obsidian wikilink中的`wiki/...`是Vault相对路径，不是相对当前笔记所在文件夹的写入路径；禁止误建`wiki/foundations/wiki/...`之类的嵌套副本。

## 目录浏览与主题拆分

- 文件树与索引都应支持“模块→子方向→论文页→原文”，不能以总索引已有链接为由省略物理分类。索引按综述、模块和方向分组，列来源ID、主归属、交叉方向、唯一页与摘要，不只按来源ID平铺。
- 论文分类目录与主题拆页是两件事。前者有实际论文即可创建；后者需要实质解释、比较或问题，不能把“不得建空主题”误用为禁止论文分目录。
- Overview承担简短地图、方向导航和关键联系。一个子方向已有独立解释、跨论文比较或问题卡，且集中页妨碍定位时，应搬移到`wiki/<模块>/<方向>.md`；不是继续把所有内容追加在Overview。当前两个模块已有实质内容，后续整理应按此评估拆分。
- 拆页保留完整论证、证据和问题状态；Overview只留摘要与入口。标题/块ID变化要更新入链，不保留平行长正文或空占位页。选读完成情况、派发与Git流水归轮次维护记录；主题可保留有解释价值的选文理由和短来源表。

## 已有目录的迁移协议

1. **盘点与映射：**读取最新Git状态，辨明他人改动；递归清点两类来源页及所有Raw，按来源ID核对身份、版本、主归属、交叉关系。建立旧路径→新路径、原件哈希、页面类型、关联文件与需修复入链的明确映射；未判明身份的文件先列异常，不批量删除或覆盖。
2. **单一协调：**整理任务取得受影响路径的写入所有权，暂停同范围摄入/笔记编辑。先保存只包含已核对内容的必要Git检查点，再分材料类型或方向小批迁移；不让独立聊天同时改同一批路径。
3. **保全来源：**Raw不可变指字节与版本证据不可改写，并非路径永远不能调整。授权的整理可移动/重命名原件，移动前后SHA-256必须一致；禁止覆盖目标、丢弃版本、转码PDF或以“清理痕迹”为由删除已归档证据。误放的生成记录按身份迁出，不擅自销毁。
4. **同步引用：**按映射一次处理原文、唯一来源页、frontmatter的sources/分类、主题、索引、规则中的实例和可维护展示的路径；保留PDF页码、标题/块锚点与表格别名转义。不依赖应用自动改链，也不只替换同名文件。只有位置变化时不重新计一次摄入或学术来源。
5. **历史可追溯：**旧日志和不可变来源内的路径文字保持原样。新增迁移记录保存映射，并追加一条简短schema日志链接它；Lint只对映射明确、目标存在且哈希一致的历史旧路径作迁移例外。当前知识页/索引必须直接使用新路径；不在旧路径复制原件来掩盖断链。
6. **迁移验收：**递归查重与清点来源ID、正文/补充/代码/网页文件，核对迁移前后数量与哈希；检查镜像归属、所有当前链接/锚点、索引覆盖、双向关联、空目录及误建嵌套。更新旧检查工具的平铺假设和路径，不能让脚本只扫根层而漏过子目录。可访问Obsidian时抽查文件树、论文页和PDF跳转；不能访问时单列未测。
7. **提交与交接：**审查移动、链接更新和未完成项，显式暂存本次文件、提交本地检查点；保留用户改动，不自动push。将仍需人工判断的归属或旧展示问题列明，不把规则更新当迁移完成。

用户明确只要求修改规则时，遵守该范围：本次不改`wiki/index.md`、`wiki/log.md`或其他知识/维护内容，不提前创建上述目标目录。迁移执行者在实际整理时记录本次规则依据及自己的迁移结果。
