# 目录组织与迁移

规则入口：[[AGENTS#1. 三层边界|AGENTS · 三层边界]]。本文件规定材料归属、论文分类及迁移验收；Ingest、Query、Auto Research、Lint共同使用，不能由各任务另定一套路径。

**2026-10-25执行状态：目录迁移已落地。** 当前路径、附件保留清单及验收见[[maintenance/migrations/2026-10-25-directory-migration|迁移记录]]；后续递归检查现有分类后维护，不按历史平铺路径创建重复来源页。

## 材料按类型归档

| 内容 | 目标位置 | 边界 |
| --- | --- | --- |
| 综述正文PDF | `raw/surveys/<题名>.pdf` | 综述单列，不混入方法、系统、评测、分析论文目录 |
| 其他论文正文PDF | `raw/papers/<模块>/<主方向>/<简称>.pdf` | 本目录只放论文正文PDF；原始渠道只有HTML时先按网页快照保存，不伪造原始PDF |
| 作者补充材料 | `raw/supplements/<来源ID>-<简称>/` | 附加PDF、作者发布的附录文件等；正文内已有附录不另拆。可区分版本，归属原论文，不另计来源 |
| 官方代码与仓库元数据快照 | `raw/code/<来源ID>-<简称>/<commit>/` | 保留所取源码的相对路径；仅保留支撑具体实现结论或明确复用的源码/配置；完整commit及来源登记通常足够，API响应有独立证据用途才保留；明确读取范围 |
| 网页原件及身份页面 | `raw/web/<来源ID>-<简称>/` | 仅在满足下述保留标准时保存HTML/响应；身份核对默认只登记URL、访问日和已核元数据，不自动归档整页 |
| 理念文章等 | `raw/articles/` | 保留原有用途，不因研究扩张变成临时杂物目录 |
| 综述知识页 | `wiki/surveys/<题名>.md` | `type: survey`；领域地图、阅读范围和主题落点 |
| 其他论文知识页 | `wiki/papers/<模块>/<主方向>/<简称>.md` | `type: paper`；唯一来源页，分析重点仍按方法/系统/评测/理论等类型调整 |
| 主题理解与综合 | `wiki/<模块>/`下的主题页 | 面向阅读的问题、机制、比较和证据，不承担完整任务队列 |

位置由**内容和出处**决定。官方README、源代码及原始API响应可以是Raw证据；Agent生成的下载清单、哈希汇总、审查报告、handoff、检索长输出、运行日志和脚本不是原始来源，不能因它们关联某篇论文就放进Raw。URL、版本、哈希等归档登记放唯一来源页或维护记录，不修改原件来补说明。

提取文本、渲染截图、未定稿讨论及临时脚本使用会话允许的临时区；用户限定项目内工作时，使用被Git忽略的`.research-tmp/`，不转存到Raw或知识页目录。确需长期保留的轮次约定、恢复点和Git检查点放`maintenance/research/<轮次>.md`；迁移映射放`maintenance/migrations/<日期>-<操作>.md`。这些是维护记录，不计学术来源或Wiki知识页，不保存全部聊天。只有实际内容需要时才建文件/目录。

## 保留标准与临时文件清理

组会型任务另按下节保留有复查用途的结构化推理记录；这一例外不扩展到全量对话或可再生缓存。

### 组会工作区与成果沉淀

- 使用 `组会/<YYYY-MM-DD>-<主题>/`，日期为准备批次，不推定实际组会日期。只在启动有实质内容的任务时创建；本轮 README 保存目标、范围、材料版本、角色与文件所有权、进度、验收和 Git 检查点，不再复制到 `maintenance/research/`。
- 原始提示词作为输入思路保存；从根目录移动时保全字节，记录旧新路径与 SHA-256。有效的本轮约定在 README 中明确说明，用户的新指令优先；提示词不自动触发派发，也不覆盖 Schema。
- 完整讨论定稿、结构化独立提案和关键质疑/修订表保留，用来复查判断怎样形成。它们不计学术来源，不套用 Wiki frontmatter 和逐文件索引要求；不保存全量 Agent 聊天、重复稿或另一份文献正文。
- 提取文本、渲染图、绘图中间文件、临时脚本和临时交付使用本批次 `.tmp/`，由 Git 忽略；这是明确的项目内临时区。验收后清理可再生材料，中断仅留最小恢复集；清理只限本任务所有的路径。
- 正式知识页保存可独立阅读的精炼成果，仍直接引用原始来源、解释推理并保留边界；组会文档是形成过程，不是新证据。知识页链接对应讨论，组会 README 链回正式成果。定稿保留当轮历史身份，知识页的后续演进不自动改写讨论记录。
- 正式成果图源与 PNG 沿用 `wiki/assets/diagrams/`；组会记录链接成果页，不另维护可分叉的正式图源。组会专用草图留临时区。Wiki 索引仅登记正式知识页，不列所有过程文件。

### 通用保留标准

**默认少存：**附加文件须回答“哪项现有结论依赖它，或哪个明确任务会复用它”。下载过、来自官方、被归档表列出、以后可能有用，都不是充分理由。论文正文和确实使用的作者补充材料保留；不因辅助文件已入Raw就永久豁免精简。

| 材料 | 默认处置 | 保留例外 |
| --- | --- | --- |
| 搜索页、身份页、下载落地页HTML，普通repo/commit/tree API响应 | 保存必要元数据、原始URL、访问日、完整commit后，清理整页/整份响应 | 独有内容支撑具体结论，或必须固定某一历史状态，且没有等价已存来源 |
| 页面渲染PNG、临时截图、提取文本、重复PDF/源码下载 | 验收后清理，可从正式原件再生成 | 已被选作正式阅读资产，或仍需定位的未解决问题所必需；先明确归属，不能整批保留 |
| 官方源码与配置 | 只保留已核读且支持实现判断的必要文件/依赖；保留仓库相对路径与完整commit | 明确安排的复现任务需要更多文件时再扩大，不因为核查过几行就存整仓库 |
| handoff、首稿/互评全文、检索长输出、一次性下载/改写脚本、缓存 | 结论、查新范围和必要恢复信息归位后清理 | 活动任务的最小恢复集；有明确复用价值的检查脚本经整理、去硬编码后可进入`scripts/`，不把一次性脚本全搬过去 |

网页快照是某时刻的HTML/响应，截图只是图像，二者不等于网页完整存档。纯身份核对通常不需要任何一种；独立网页论据确需保留时，登记其支撑主张及版本，动态页面还须说明快照的缺失范围。删去身份快照后保留元数据核对记录，不再声称当前仓库含有可离线核查的该网页。

**清理时点与责任：**每次任务验收及轮次结束，由协调者检查临时区，移交必要结果后清理本任务产生的可再生文件；失败/中断只留明确的最小恢复集，标注用途、负责人及下一清理节点，恢复或结束后处理。`.gitignore`只防提交，不代表已清理；维护记录也不是垃圾归档区。其他活动会话的临时文件不能按时间或扩展名批量清空。

**已归档辅助文件的精简：**用户本次已要求筛选可复用材料，后续整理任务可按本规则删除无独立用途的网页/元数据、冗余代码快照及过程文件，无需逐文件重复确认。先核对正文引用和依赖，区别实质引用与自动生成的sources/归档表；必要结论转为可追溯的元数据记录或保留原证据，无法做到则保留并说明。保留中的Raw字节不修改；正文PDF、已使用的补充材料、唯一实质证据和未辨明的用户文件不在此次自动精简范围。

对已提交的辅助文件，精简前登记路径、哈希、来源URL、删除理由及可恢复的既有Git提交；更新当前sources、哈希清单、链接和“本地已存”表述，旧日志不回写，新日志记一次整理结果。历史删除链接只有登记齐全且可恢复时才列为已说明精简项，当前断链仍须修复。临时缓存无需逐个写长日志，按类别记清理数量/体积与保留例外即可；不把缓存先提交Git来获得删除资格，不改写Git历史。

递归删除前，解析绝对路径并验证目标位于本项目获准临时区，检查符号链接/重解析点，不跨目录或跟随链接删除；使用同一Shell的原生LiteralPath操作，不拼接跨Shell删除命令。归档文件按审核后的明确清单处理，不按通配符删除整个Raw目录。

## 一个主归属，多个主题关系

论文与笔记使用相同的模块、方向和文件简称，相对路径镜像；综述两侧同样对应。简称确认后尽量稳定，整理目录不顺便批量改标题。来源ID、标题和DOI/arXiv用于身份判断，目录只是主归属，移动不能改变来源ID。

普通论文页增加`primary_direction`（例如`harness/memory`）；有实际交叉关系时再加列表字段`related_directions`。综述不强制分配技术主方向。主归属按主要贡献与本库使用目的判断，不能只因最先在哪个队列读到就永久归类；多方向工作选一个主落点并记录理由，其他方向用链接及元数据关联，不复制PDF、论文页或用软链接制造多份入口。

当前13个方向采用以下对应名称；这是共享词表，不是要求预建所有空目录：

| 模块 | 方向 | 目录名 |
| --- | --- | --- |
| `harness` | 循环与工作流 | `workflows` |
| `harness` | 上下文与记忆 | `memory` |
| `harness` | 工具、MCP与技能 | `tools` |
| `harness` | 编排 | `orchestration` |
| `harness` | Hooks与中间件 | `hooks` |
| `harness` | 验证 | `verification` |
| `optimization` | 架构基础 | `architecture` |
| `optimization` | 数据与环境合成 | `data-environments` |

确有不适配现有分类的材料时，补充有内容、有理由的类别并同步本词表，不强塞，也不生成长期堆积的“其他/未分类”目录。多领域综述仍归综述目录；一般方法论文不会因带Related Work而变成综述。

创建路径一律从Vault根目录解析，先验证解析后的绝对路径在本项目内。Obsidian wikilink中的`wiki/...`是Vault相对路径，不是相对当前笔记所在文件夹的写入路径；禁止误建`wiki/foundations/wiki/...`之类的嵌套副本。

## 目录浏览与主题拆分

- 文件树与索引都应支持“模块→子方向→论文页→原文”，不能以总索引已有链接为由省略物理分类。索引按综述、模块和方向分组，列来源ID、主归属、交叉方向、唯一页与摘要，不只按来源ID平铺。
- 论文分类目录与主题拆页是两件事。前者有实际论文即可创建；后者需要实质解释、比较或问题，不能把“不得建空主题”误用为禁止论文分目录。
- Overview承担简短地图、方向导航和关键联系。一个子方向已有独立解释、跨论文比较或问题卡，且集中页妨碍定位时，应搬移到`wiki/<模块>/<方向>.md`；不是继续把所有内容追加在Overview。当前两个模块已有实质内容，后续整理应按此评估拆分。
- 拆页保留完整论证、证据和问题状态；Overview只留摘要与入口。标题/块ID变化要更新入链，不保留平行长正文或空占位页。选读完成情况、派发与Git流水归轮次维护记录；主题可保留有解释价值的选文理由和短来源表。

## 已有目录的迁移协议

1. **盘点与映射：**读取最新Git状态，辨明他人改动；递归清点两类来源页及所有Raw，按来源ID核对身份、版本、主归属、交叉关系。建立旧路径→新路径、原件哈希、页面类型、关联文件与需修复入链的明确映射；未判明身份的文件先列异常，不批量删除或覆盖。
2. **单一协调：**整理任务取得受影响路径的写入所有权，暂停同范围摄入/笔记编辑。先保存只包含已核对内容的必要Git检查点，再分材料类型或方向小批迁移；不让独立聊天同时改同一批路径。
3. **保全来源：**Raw不可变指字节与版本证据不可改写，并非路径永远不能调整。授权的整理可移动/重命名原件，移动前后SHA-256必须一致；禁止覆盖目标、丢弃正文版本或转码PDF。辅助快照与误放的生成记录按保留标准审查，满足精简条件后清理，不强制搬到另一个目录继续堆积。
4. **同步引用：**按映射一次处理原文、唯一来源页、frontmatter的sources/分类、主题、索引、规则中的实例和可维护展示的路径；保留PDF页码、标题/块锚点与表格别名转义。不依赖应用自动改链，也不只替换同名文件。只有位置变化时不重新计一次摄入或学术来源。
5. **历史可追溯：**旧日志和不可变来源内的路径文字保持原样。新增迁移记录保存映射，并追加一条简短schema日志链接它；Lint只对映射明确、目标存在且哈希一致的历史旧路径作迁移例外。当前知识页/索引必须直接使用新路径；不在旧路径复制原件来掩盖断链。
6. **迁移验收：**递归查重与清点来源ID、正文/补充/代码/网页文件，核对迁移前后数量与哈希，并用经审核的精简清单解释删除差额；检查镜像归属、所有当前链接/锚点、索引覆盖、双向关联、空目录及误建嵌套。更新旧检查工具的平铺假设和路径，不能让脚本只扫根层而漏过子目录。可访问Obsidian时抽查文件树、论文页和PDF跳转；不能访问时单列未测。
7. **提交与交接：**审查移动、链接更新和未完成项，显式暂存本次文件、提交本地检查点；保留用户改动，不自动push。将仍需人工判断的归属或旧展示问题列明，不把规则更新当迁移完成。

用户明确只要求修改规则时，不自动执行资料迁移；本次目录整理另有用户明确授权，执行结果见迁移记录。
