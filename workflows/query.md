# Query 清单

规则入口：[[AGENTS#5. Query：有证据地回答并积累|AGENTS · Query]]。用户提问或已授权的 [[workflows/autoresearch|Auto Research]] 轮次均可触发。

1. 从[[wiki/index|索引]]和模块/方向目录定位问题；读取相关主题及唯一来源页。递归覆盖`wiki/surveys/`和`wiki/papers/`子目录，不按旧平铺路径猜测、不因找不到旧位置重建来源页；迁移映射按[[workflows/structure|目录规则]]回查。
2. 回到原文核对关键证据、适用条件和阅读范围。没有直接证据时明确说明，不能把综述参考文献当作已核读论文。
3. 回答问题：论点紧邻来源与页码；区分综述观点、转述、本库推断及待检验问题。需要新材料时接 [[workflows/ingest|Ingest]]。
4. 将有长期价值的综合、比较、纠错或问题写回最相关的主题；独立内容已足且Overview妨碍定位时，按目录规则搬移拆页并保留概览导航，不能把“优先现有页”理解为无限追加。没有持久新认识则不造页。按[[workflows/presentation|阅读表达清单]]设计图文，图放到对应问题处；修改论断时检查图与导航，普通简短问答不强制图解。
5. 有变更则按需同步索引、交叉引用和日期，运行局部 [[workflows/lint|Lint]]。形成持久的新认识、重要问题或实质纠错时，按 [[AGENTS#7. 索引与追加日志|日志规则]] 合并记一条简短 `query` 日志；普通问答、无知识变更的解释和轻微编辑不记日志。

查询结果不是新的论文证据。未来再次引用时仍追溯其原始来源。

## 组会型讨论

用户要求为组会形成 insight 时，可接 [[workflows/brainstorm#综述内讨论与组会交付|综述内讨论模式]]。完整讨论、独立提案与修订保存在 [[workflows/structure#组会工作区与成果沉淀|组会工作区]]，正式 Wiki 仅接收经核对且可独立阅读的精炼成果，两处互链。只读综述的材料限制同样约束概述笔记中的转引；证据不足就记录未知，不自动启动 Ingest、查新或实验。入库不将归纳、假设升级成已验证结论。

## 跨论文综合与头脑风暴

先围绕同一个问题比较**具体失败、改变对象、机制、成立前提、任务/模型/harness/预算/指标和证据覆盖**，再判断哪些结果能放在一起解释。可以用表格展示机制和条件，不能把不可比的性能数字排列成优劣。重点寻找共同前提、条件不同造成的表面冲突、主张与证据的距离，以及有结构依据的机制迁移，不拼接论文摘要。

需要构思或审查候选问题时接 [[workflows/brainstorm|Brainstorm]]：固定共同证据，先独立判断，再互评、补读和修订。缺少原文时回 Ingest，缺少证据时保留未知；同模型多人同意不增加证据强度。主 Agent 审核交付，单篇解释回原论文 subagent 修订，共享主题遵循 [[workflows/autoresearch#派发与共享写入|串行写入协议]]。

交付优先说清“原判断是什么—哪条证据改变了它—仍有什么分歧—下一条证据是什么”。区分理解缺口、本库证据缺口与限定查新范围内的候选研究缺口。候选问题及被已有工作覆盖的简短理由写回相关主题；零个新 idea、关闭一个误判问题都可以是有价值的结果，不创建平行 idea 仓库。

展示变化须区分文件检查与 Obsidian 实测结果。纯展示改进若构成实质变化，可按第 7 节记录一次；轻微排版不另记日志。
